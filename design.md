# Design

## Данные
    Task = { id: string, title: string, hours: number, done: boolean }
    State = { tasks: Task[], filter: 'all' | 'active' }

- `id` выдаётся счётчиком (`t1`, `t2`, …). Следующий номер = max(существующих) + 1. `crypto.randomUUID` не используется: в контексте file:// он доступен не во всех браузерах.
- `hours` хранится как число. Значения кратны 0,5, поэтому они точно представимы в двоичной плавающей точке и суммы не накапливают погрешность.
- Фильтр — состояние UI. Он не сохраняется в данных задач.

## Доменные функции (чистые, без DOM)
В варианте B они лежат в `domain.mjs`, в варианте A — в отдельном блоке внутри `<script>`.

- `validateInput(rawTitle, rawHours)` → `{ ok: true, value: { title, hours } }` или `{ ok: false, errors: { title?, hours? } }`
  - title: `rawTitle.trim()`, пустая строка — ошибка «Введите название».
  - hours: `rawHours.trim()`; пустая строка — ошибка «Укажите часы» (до любого преобразования в число, поэтому пустое не превращается в 0). Запятая заменяется на точку, затем `Number(...)`. Ошибка, если `!Number.isFinite(h)`, `h < 0.5`, `h > 24` или `!Number.isInteger(h * 2)`. Текст ошибки: «Часы: от 0,5 до 24, шаг 0,5».
- `addTask(tasks, {title, hours})` → новый массив с задачей `{ id, title, hours, done: false }`.
- `removeTask(tasks, id)` → новый массив без задачи.
- `toggleTask(tasks, id)` → новый массив, у задачи `done` инвертирован.
- `visibleTasks(tasks, filter)` → `all`: все задачи; `active`: задачи с `done === false`.
- `summary(tasks)` → `{ totalHours, doneHours, progress }`:
  - `totalHours = Σ hours`
  - `doneHours = Σ hours, где done`
  - `progress = totalHours === 0 ? 0 : Math.round(100 * doneHours / totalHours)`

`summary` всегда получает полный `tasks`, никогда не результат `visibleTasks`. Так требование 4 выполняется по построению.

## Контрольные расчёты
| Состояние                     | total | done | progress |
|-------------------------------|-------|------|----------|
| Старт                         | 8     | 2    | 25       |
| «Практика» готова             | 8     | 6    | 75       |
| Фильтр «Активные» (со старта) | 8     | 2    | 25       |
| Все удалены                   | 0     | 0    | 0        |
| Старт + «Конспект» 1,5 ч      | 9,5   | 2    | 21       |

## UI
- Форма: `<label>Название</label>` + текстовое поле; `<label>Часы</label>` + `input` (type="text" с inputmode="decimal", чтобы принимать и запятую, и точку; проверка в доменной функции); кнопка «Добавить».
- Ошибки: элемент под полем, связан через `aria-describedby`; у поля `aria-invalid="true"`, у элемента ошибки `role="alert"` или `aria-live`. При ошибке значения полей не сбрасываются. При успехе форма очищается.
- Список: чекбокс с подписью «Выполнено: <название>», текст «<название> — <часы> ч», кнопка удаления с `aria-label="Удалить <название>"`.
- Фильтр: группа радиокнопок «Все» / «Активные» с `<fieldset><legend>`.
- Сводка: «Всего: 8 ч · Выполнено: 2/8 ч · Прогресс: 25%» плюс `<progress>` или полоса с текстовым значением. Часы выводятся с запятой (2, 1,5).
- Рендер: одна функция `render(state)` после каждого изменения состояния.

## Вёрстка 390 px
- `<meta name="viewport" content="width=device-width, initial-scale=1">`.
- Без фиксированных ширин в px больше вьюпорта; `max-width` и проценты; `box-sizing: border-box`.
- Строки формы и списка на flex с `flex-wrap: wrap`; у текстовых элементов `min-width: 0` и `overflow-wrap: anywhere` для длинных названий.

## Хранилище (опционально)
- Ключ: `tracker-v2.tasks`, значение — JSON-массив задач.
- Загрузка: `try { getItem → JSON.parse → проверка структуры }`. Если ключа нет — стартовый пример. Если данные повреждены или чтение выбросило исключение — стартовый пример в памяти и сообщение.
- Запись после каждого изменения в `try/catch`. При исключении — сообщение «Сохранение недоступно…», работа продолжается в памяти, повторные ошибки не дублируют сообщение.
- Пустой массив сохраняется как есть: после удаления всех задач и перезагрузки список остаётся пустым, стартовый пример не возвращается.
- Ограничение file://: поведение localStorage для страниц file:// зависит от браузера. Хранилище может быть общим для всех локальных файлов, изолированным для каждого файла, очищаться или быть недоступным (например, в приватном режиме или из-за политики безопасности). Сохранение между перезапусками при file:// не гарантируется; гарантируется только понятное сообщение и работа в памяти.

## Различия вариантов
- **A (`tracker-v2.html`):** классический `<script>` (не модуль), поэтому файл работает при открытии через file://. Встроенных автотестов нет, проверка ручная по сценариям.
- **B:** `index.html` подключает `styles.css` и `<script type="module" src="app.mjs">`; `app.mjs` импортирует `domain.mjs`. Ограничение: многие браузеры (например, Chromium) блокируют ES-модули при file:// из-за CORS. Для запуска B нужен локальный статический сервер, например `python3 -m http.server`. Это не внешняя зависимость и не CDN. `domain.mjs` не обращается к DOM и `localStorage`.
- **Тесты B:** `tests/acceptance.test.mjs` на встроенном `node:test` и `node:assert`, запуск `node --test tests/`. Тестируются доменные функции по сценариям WHEN/THEN. UI и ширина 390 px автотестами не покрываются.
