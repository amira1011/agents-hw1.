# Tracker Specification

## ADDED Requirements

### Requirement: Модель задачи и стартовые данные
Система MUST хранить задачи как список объектов `{ id, title, hours, done }`.
`id` MUST быть уникальным в пределах списка. Если сохранённых данных нет, при первом запуске MUST загружаться стартовый пример: «Чтение» 2 ч, done=true; «Практика» 4 ч, done=false; «Повторение» 2 ч, done=false.

#### Scenario: Стартовые значения
- **WHEN** трекер открыт впервые со стартовым примером
- **THEN** показано: всего 8 ч, выполнено 2 ч (2/8), прогресс 25%

### Requirement: Добавление задачи
Система MUST добавлять задачу в данные, только если ввод валиден. После успешного добавления задача MUST появиться в данных, а итог и прогресс MUST пересчитаться. Новая задача MUST создаваться с `done=false`.

#### Scenario: Валидная задача добавлена
- **WHEN** введено название «Конспект» и часы 1,5, затем нажата кнопка «Добавить»
- **THEN** в данных 4 задачи, всего 9,5 ч, выполнено 2 ч, прогресс 21%

### Requirement: Валидация названия
Название MUST быть непустым после trim. При ошибке задача MUST NOT добавляться. Текст ошибки MUST быть виден рядом с полем названия. Введённые значения формы MUST сохраняться.

#### Scenario: Пустое название
- **WHEN** название пустое или состоит только из пробелов, часы равны 2, нажата кнопка «Добавить»
- **THEN** задача не добавлена, рядом с полем названия видна ошибка, значение часов «2» осталось в поле

### Requirement: Валидация часов
Часы MUST быть конечным числом в диапазоне 0,5–24 с шагом 0,5. Пустое значение MUST считаться ошибкой и MUST NOT приравниваться к нулю. Отрицательное число, ноль, значение вне диапазона, значение не кратное 0,5 и нечисловой ввод MUST отклоняться. Ошибка MUST быть видна рядом с полем часов. Введённые значения формы MUST сохраняться.

#### Scenario: Пустые часы
- **WHEN** название «Тест», поле часов пустое, нажата кнопка «Добавить»
- **THEN** задача не добавлена, рядом с полем часов видна ошибка, название «Тест» осталось в поле

#### Scenario: Отрицательные часы
- **WHEN** название «Тест», часы −1, нажата кнопка «Добавить»
- **THEN** задача не добавлена, рядом с полем часов видна ошибка

#### Scenario: Граничные значения
- **WHEN** вводятся часы 0,5 и 24
- **THEN** оба значения принимаются
- **WHEN** вводятся часы 0, 0,3, 24,5 или 25
- **THEN** каждое значение отклоняется с ошибкой у поля часов

### Requirement: Удаление задачи
Удаление MUST убирать задачу из данных. Итог и прогресс MUST пересчитываться.

#### Scenario: Удалены все задачи
- **WHEN** удалены все задачи
- **THEN** итог 0 ч, выполнено 0 ч, прогресс 0%; на экране нет NaN и Infinity

### Requirement: Переключение статуса
Переключение `done` MUST менять значение в данных. Итог и прогресс MUST пересчитываться.

#### Scenario: «Практика» отмечена готовой
- **WHEN** в стартовом примере «Практика» отмечена выполненной
- **THEN** выполнено 6/8 ч, прогресс 75%

### Requirement: Расчёт прогресса
Прогресс MUST вычисляться как округление(100 × сумма часов задач с done=true / сумма часов всех задач). При пустом списке прогресс MUST быть 0%. Результат MUST NOT быть NaN или Infinity.

#### Scenario: Пустой список
- **WHEN** задач нет
- **THEN** прогресс 0%

### Requirement: Фильтр видимого списка
Система MUST предоставлять фильтр «Все» / «Активные». Фильтр MUST влиять только на видимый список. Итоговые часы и прогресс MUST считаться по всем задачам.

#### Scenario: Включён фильтр «Активные»
- **WHEN** в стартовом примере выбран фильтр «Активные»
- **THEN** в списке видны только «Практика» и «Повторение», всего по-прежнему 8 ч, прогресс остаётся 25%

### Requirement: Доступность и узкий экран
Каждое поле и каждая кнопка MUST иметь доступную подпись (label или aria-label). На ширине вьюпорта 390 px интерфейс MUST оставаться читаемым без горизонтального скролла.

#### Scenario: Ширина 390 px
- **WHEN** страница открыта при ширине вьюпорта 390 px со стартовыми данными и длинным названием задачи
- **THEN** горизонтальной прокрутки нет, `document.documentElement.scrollWidth` ≤ 390, весь текст читаем

### Requirement: Автономность
Реализация MUST работать без CDN, внешних библиотек, сетевых запросов и API-ключей.

#### Scenario: Работа без сети
- **WHEN** трекер открыт без подключения к интернету
- **THEN** все функции работают, сетевых запросов к внешним ресурсам нет

### Requirement: Сохранение в localStorage (опционально)
Если улучшение реализуется, система MUST сохранять задачи в localStorage после каждого изменения и загружать их при старте. Если хранилище недоступно или данные в нём повреждены, система MUST показать понятное сообщение и продолжить работу в памяти без сбоев.

#### Scenario: Хранилище недоступно
- **WHEN** обращение к localStorage выбрасывает исключение
- **THEN** видно сообщение «Сохранение недоступно — изменения будут потеряны при закрытии страницы», добавление, удаление и переключение работают

#### Scenario: Данные переживают перезапуск
- **WHEN** хранилище доступно, задача добавлена, страница перезагружена
- **THEN** добавленная задача на месте
